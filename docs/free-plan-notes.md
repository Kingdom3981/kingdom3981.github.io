# Free-Plan Notes Verified 2026-09-14

These constraints were checked against official documentation while building this project.

- GitHub Pages hosts static HTML, CSS, and JavaScript from a repository and supports both user sites and project sites. Project sites use `https://OWNER.github.io/REPOSITORY/`. Source: [GitHub Pages overview](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).
- Custom GitHub Pages workflows need `pages: write` and `id-token: write`; this project uses artifact deployment instead of relying on a bot commit to trigger another Pages build. Source: [GitHub custom Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
- GitHub Actions standard runners are free for public repositories and GitHub Pages. GitHub Free private repositories include 2,000 minutes/month and 500 MB artifact storage. Source: [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions).
- Scheduled workflows run in UTC, can be delayed during high load, and scheduled workflows in public repositories can be disabled after 60 days without repository activity. Sources: [events that trigger workflows](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows) and [troubleshooting workflows](https://docs.github.com/en/actions/how-tos/troubleshoot-workflows).
- OneSignal Free currently lists web push as max 10,000 subscribers per send, API Send Access as unlimited, 6 audience segments, and 6 data tags. Source: [OneSignal pricing](https://onesignal.com/pricing).
- OneSignal scheduled push can be set with `send_after`; push overview says scheduled sends can be up to 30 days in advance. Source: [OneSignal push overview](https://documentation.onesignal.com/docs/en/push).
- OneSignal create notification supports `idempotency_key`, valid for 30 days, and cancel message can stop scheduled or currently outgoing messages but may not prevent delivery once sending is already in progress. Sources: [Create push notification](https://documentation.onesignal.com/reference/push-notification) and [Cancel message](https://documentation.onesignal.com/reference/cancel-message).
- OneSignal web push requires HTTPS, a publicly accessible service worker on the same origin, and explicit user permission. Source: [OneSignal web push setup](https://documentation.onesignal.com/docs/en/web-push-setup).
- iPhone/iPad web push is supported for Home Screen web apps on iOS/iPadOS 16.4 or later, not normal Safari tabs. Apple also says permission should be requested from a user gesture. Source: [Apple web push documentation](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers).
